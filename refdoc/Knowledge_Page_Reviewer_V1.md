\# Knowledge Page Reviewer V1





\## Purpose



This document defines the self-review checklist for AI-generated calculus knowledge pages.



The reviewer should evaluate whether a new knowledge page satisfies the product requirements before human review.





Important:



The reviewer should NOT modify template files automatically.



The reviewer can only:



\- identify issues;

\- suggest improvements;

\- refine the current topic page.





Do not modify approved knowledge pages.







\---



\# 1. Product Consistency Review





Check:



Does the page follow:



\- Knowledge\_Page\_Template\_V3\_1.md?

\- Visual\_Interaction\_Template\_V3\_1.md?

\- Hero Card design philosophy?





Questions:



✓ Does it look like part of the same product?



✓ Is the visual style consistent?



✓ Is the page structure consistent?







\---



\# 2. Mathematical Accuracy Review





Check:





\## Concepts



✓ Is the mathematical definition correct?



✓ Is the Chinese explanation academically accurate?





\## Formulas



✓ Are formulas correct?



✓ Are symbols clearly defined?



✓ Are mathematical steps logically valid?



Mathematical Expression Review



Check:



✓ Are important fractions displayed using proper fraction formatting?



Reject if:



\- Slash notation creates ambiguity.

\- Numerator and denominator relationships are unclear.



\---



\# 3. Visual Understanding Review





Important:



Visuals must explain mathematics.





Check:





✓ Does every visual element have mathematical meaning?



✓ Are graphs mathematically correct?



✓ Are points located on the objects they represent?



✓ Are curves, lines, and labels meaningful?





Avoid:



\- decorative graphs;

\- unrelated icons;

\- visual elements without mathematical purpose.







\---



\# 4. Hero Card Review





Check:



✓ Does the Hero Card show a concept-defining formula?



✓ Is the formula understandable without reading later sections?



Reject if:



\- The formula is only an example problem.

\- The meaning is unclear.

\- Arbitrary numbers are used without explanation.



\## Formula



✓ Is the formula the visual center?



✓ Is the formula readable?



✓ Are long formulas displayed properly?





\## Visual Meaning



✓ Do colors represent mathematical relationships?



✓ Are visual elements concept-specific?



✓ Are there unnecessary decorative elements?



\## Hero Card Concept Review





Check:





✓ Can students understand the concept before reading later sections?



✓ Does the Hero Card explain the idea, not only the final formula?





Reject if:



\- Formula requires later explanation to understand.

\- Formula is correct but conceptually disconnected.

\- Hero Card feels like a textbook equation display.



\## Hero Card Formula Rendering Review





Check:



✓ Is the complete formula visible?



✓ Are all symbols displayed correctly?



✓ Does the formula preserve mathematical structure?





Reject if:



\- Formula is clipped.

\- Important symbols are missing.

\- The equation cannot be understood independently.

\---



\# 5. Learning Experience Review





Check:





\## Before Class Goal



Can a student understand:



\- What is this concept?

\- Why is it needed?

\- How is it used?





\## English Learning



Check:



\- Terminology

\- Pronunciation

\- Classroom English





\---



\# 6. Interaction Review





Check:





✓ Audio works



✓ Navigation works



✓ Step-by-step examples are clear



✓ Quick Check tests understanding



\# 7.  Layout Review





Check:



✓ Are titles readable?



✓ Are headings properly spaced?



✓ Are there any overlapping elements?



✓ Are grouped cards visually balanced?



✓ Are cards in the same row equal height?



Reject if:



\- Text overlaps.

\- Important labels are too small.

\- Card heights are inconsistent.

\---

\# 8. Visual Interaction Review:
Check:

✓ Are only active steps visible?

Reject if:

* Future steps distract from current step.
* Multiple steps compete visually.
* 

\# 9. Formula Review:
Check:

✓ Is mathematical notation professionally typeset?

Reject if:

* Fractions overlap.
* Formula elements collide.
* Superscripts/subscripts are unclear.

\# 10. Visual Review

Check:

✓ Do geometric labels overlap objects?

✓ Are points, lines, and labels clearly separated?



\# 11. Mathematical Explanation Review

Check:

✓ Does the explanation distinguish derivation and interpretation?



Reject if:

* A geometric analogy is presented as the mathematical derivation.

\# 12. Formula Visualization Review

Check:



✓ Are all formulas fully visible?

✓ Are equations readable without artificial line breaks?

✓ Does the layout adapt to formula length?



Reject if:

* Formula is clipped.
* Formula structure is broken.
* Mathematical meaning is lost due to wrapping.

\# 13. Self-Improvement Loop





After generation:





If issues exist:





1\. Identify the problem.

2\. Classify the problem:



\- Content issue

\- Visual issue

\- Layout issue

\- Mathematical issue





3\. Fix only the current topic page.



Do not:



\- change global templates;

\- modify existing approved pages.





Maximum iteration:



5 rounds.





If still not satisfactory:



Report remaining issues for human review.
